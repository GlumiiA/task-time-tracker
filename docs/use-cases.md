# Use Cases

## Акторы

| Актор | Описание |
|---|---|
| User | Авторизованный пользователь системы |
| Employee | Сотрудник, которому назначаются задачи |
| System | Backend-сервис Task Time Tracker |

## Список use cases

| ID | Use Case | Endpoint |
|---|---|---|
| UC-01 | Авторизация пользователя | POST /api/auth/login |
| UC-02 | Создание задачи | POST /api/tasks |
| UC-03 | Получение списка задач | GET /api/tasks |
| UC-04 | Получение задачи по ID | GET /api/tasks/{id} |
| UC-05 | Обновление задачи | PUT /api/tasks/{id} |
| UC-06 | Изменение статуса задачи | PATCH /api/tasks/{id}/status |
| UC-07 | Назначение исполнителя | PATCH /api/tasks/{id}/assignee |
| UC-08 | Создание записи времени | POST /api/time-records |


## UC-02: Создание задачи

| Поле | Значение |
|---|---|
| Актор | User |
| Предусловие | Пользователь авторизован |
| Постусловие | Задача создана в системе |

### Основной сценарий
1. Пользователь отправляет запрос на создание задачи.
2. Система валидирует входные данные.
3. Система сохраняет задачу.
4. Система возвращает созданную задачу.

### Альтернативные сценарии
- Если название пустое — возвращается 400 Bad Request.
- Если пользователь не авторизован — возвращается 401 Unauthorized.

### Проверки
- задача создается со статусом по умолчанию;
- обязательные поля валидируются;
- ответ содержит ID созданной задачи.

## UC-08: Создание записи времени

| Поле | Значение |
|---|---|
| Актор | Employee |
| Предусловие | Пользователь авторизован, задача существует |
| Постусловие | Запись времени сохранена |

### Основной сценарий
1. Сотрудник отправляет запись о затраченном времени.
2. Система проверяет существование задачи.
3. Система валидирует время начала и окончания.
4. Система сохраняет TimeRecord.

### Альтернативные сценарии
- Если задача не найдена — 404 Not Found.
- Если время окончания раньше времени начала — 400 Bad Request.
- Если обязательные поля не заполнены — 400 Bad Request.
